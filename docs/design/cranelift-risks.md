# Cranelift risk register

Each item records a backend mismatch and the behavior CCC requires. A feature is enabled for a target only when its capability test and cross-linked tests pass; otherwise CCC emits a hard diagnostic at the first semantic use.

## Risk register

| #   | Problem                             | Required strategy                                                                                                                                                                                                                                                                                                                                                                                                                |
| --- | ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **C struct-by-value ABI**           | Per-target classifiers produce immutable [`AbiPlan`s](abi-and-varargs.md). Aggregate splitting, hidden returns, stack placement, and copy glue are tested against psABI references and cross-linked binaries.                                                                                                                                                                                                                    |
| 2   | **Variadic calls and definitions**  | Do not rely on cg_clif's integer-only call workaround. Use native backend support when complete, otherwise generated call and callee-entry bridges that handle special registers, register-save areas, stack overflow areas, indirect calls, and the target `va_list`; see [ABI & variadics](abi-and-varargs.md).                                                                                                                |
| 3   | **f80 and binary128 `long double`** | Preserve the target representation. Binary128 uses verified `f128`/libcall lowering; x86 f80 uses runtime arithmetic plus assembly boundary bridges for x87 arguments and returns. Missing arithmetic or ABI support is a hard error; f64 substitution requires explicit compatibility mode.                                                                                                                                     |
| 4   | **GNU inline assembly**             | The AST retains template, operands, constraints, alternatives, ties, early-clobber, clobbers, volatility, and goto labels. A side object is valid only when an explicit marshalling stub preserves those semantics. Stack-sensitive asm, `asm goto`, local control flow, or unsupported constraints require a whole-function assembly path or a hard error; they are never converted into an ordinary helper call.               |
| 5   | **VLAs and `alloca`**               | Raw stack-pointer mutation is forbidden in ordinary CLIF. CCC requires a backend operation that allocates/restores dynamically sized aligned stack storage while participating in frame layout, call alignment, probes, and debug/unwind metadata. Until the pinned backend provides that contract, affected functions are rejected rather than implemented with a callee helper whose allocation would be invalid after return. |
| 6   | **TLS**                             | Map the effective TLS model to supported Cranelift/object relocations and validate linker results per format. | 7   | **C11 atomics**                     | Preserve C orders in CCC-IR, conservatively map supported operations, and use `libatomic`/CCC helpers for unsupported widths or alignments. | 8   | **Debug information**               | Source locations feed line tables; a CCC DWARF layer using gimli emits compilation units, types, scopes, variables, frame information, and relocation-bearing sections. Backend `SourceLoc` support is only the input mapping.                                                                                                                                                                                                   |
| 9   | **PIC, PIE, and relocation models** | Select matching codegen and linker modes from the effective configuration. Probe the target driver default and explicitly disable PIE for non-PIE output; never mix incompatible relocations and driver defaults.                                                                                                                                                                                                                |
| 10  | **ELF vs Mach-O**                   | Object-format adapters own section names, symbol/visibility rules, relocations, TLS, constructors, unwind sections, and shared-library naming. `cranelift-object` is verified by object inspection rather than assumed to cover every platform rule.                                                                                                                                                                             |
| 11  | **CPU features and SIMD**           | Normalize `-march`/`-mcpu`/`-m*` into one feature set used by predefined macros, type legality, ABI classification, and Cranelift ISA flags. A vector type or intrinsic is enabled only when all four agree.                                                                                                                                                                                                                     |
| 12  | **`setjmp`/`longjmp`**              | Mark calls as returns-twice in CCC-IR. Materialize locals live across the call, preserve volatile locals, insert compiler/memory barriers, disable incompatible motion/tail-call transformations, and require a backend capability test proving register allocation and frame restoration. Without that proof, diagnose the call.                                                                                                |
| 13  | **Large frames and stack probes**   | Compute static and dynamic worst-case obligations where possible, use target probe rules, and ensure probes compose with dynamic allocation and guard pages. Probe symbols are resolved through the target runtime, not the host runtime.                                                                                                                                                                                        |
| 14  | **Compiler-emitted helper calls**   | A target runtime manifest maps every helper signature and symbol to compiler-rt, libgcc, libatomic, libc, or a versioned CCC shim. Link-time availability is probed; helper ABI is covered by cross-linked tests.                                                                                                                                                                                                                |
| 15  | **`_Complex`**                      | Expose the capability only with typed pair operations, floating-point edge-case tests, libc/header support, and per-target ABI plans. Otherwise advertise `__STDC_NO_COMPLEX__` and reject semantic use.                                                                                                                                                                                                                         |
| 16  | **Optimization expectations**       | Each `-O` level has a documented pass set and predefined-macro behavior. Higher levels may share a pass set, but the driver does not claim an optimization or aliasing contract it does not implement.                                                                                                                                                                                                                           |

Cross-function label values remain undefined behavior and are diagnosed where detectable. Lua's default GNU-profile build selects computed-goto VM dispatch, so the Lua corpus gate depends on this lowering.                                                                                    |

## Dynamic stack capability contract

The required backend operation takes runtime size and power-of-two alignment, performs overflow checking/probing, returns a stable pointer, and supports a stack-save token restored on every normal edge that leaves the VLA scope. Semantic analysis rejects jumps into a VLA scope; IR lowering inserts restores for `break`, `continue`, `goto`, and return edges. Nonlocal exit follows the platform `longjmp` contract. CCC will prefer an upstream Cranelift facility; a private backend extension must carry the same verifier and unwind/frame tests.

## Returns-twice capability contract

Functions containing a returns-twice call use a conservative lowering profile: affected locals are memory-resident, memory-sensitive optimization is disabled across the call, frame pointers are retained where required, and no tail call crosses the boundary. Tests modify volatile and non-volatile locals around `setjmp`, perform nested calls, and cross-link against the system implementation at every optimization level. This profile is enabled only after emitted-code tests prove the pinned backend behavior.
