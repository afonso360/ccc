# Cranelift risk register

Each item records a backend mismatch and the behavior CCC requires. A feature is enabled for a target only when its capability test and cross-linked tests pass; otherwise CCC emits a hard diagnostic at the first semantic use.

## Runtime-sized automatic storage contract

Runtime extents are evaluated once at each parameter, declaration, typedef, or
evaluated type-name site and retained for multidimensional pointer strides and
layout. `RuntimeSize` computes the complete byte size with checked `size_t`
arithmetic; allocation, runtime `sizeof`, and dynamic pointer operations consume
that explicit result. CCC-IR assigns each syntactic runtime-sized object its own
provider-neutral storage identity and an explicit allocation effect.

The hosted lowering gives each identity a fixed `{base, capacity}` state slot.
It reuses the existing allocation when capacity is sufficient, otherwise grows
it with `realloc`, and returns a stable address aligned to the greater of the
declared alignment and the target VLA minimum. A nonpositive bound, arithmetic
overflow, or provider failure enters a non-returning failure path. Physical
capacity may remain reserved after the C lifetime ends, but it is unreachable
from defined C execution, bounded by the number of syntactic declarations, and
released on every ordinary function return after the return value is evaluated.

Semantic analysis rejects named-goto and switch ingress that bypasses a
variably modified declaration. Until computed dispatch can prove a target's
declaration path, it is rejected in any function containing a variably modified
declaration.

The selected hosted provider is the per-invocation arena recorded by
[ADR-0011](../adr/0011-arena-backed-runtime-sized-automatic-storage.md).
Automatic object allocation and runtime layout are enabled on every supported
hosted target, and `__STDC_NO_VLA__` is therefore absent.

## Native dynamic-stack capability contract

GNU stack-allocation builtins require a backend operation that takes a runtime
size and power-of-two alignment, allocates and restores native stack space, and
participates in fixed-slot and spill addressing, call alignment, target probes,
debug information, and unwind metadata. CCC will pursue that facility upstream.
It will not carry a private Cranelift fork or substitute an ordinary helper or
assembly thunk. Arena-backed ISO VLA support does not enable this capability.

## Returns-twice capability contract

Functions containing a returns-twice call use a conservative lowering profile:
all automatic objects are memory-resident, the call carries read/write effects,
frame pointers are retained, and no tail-call transform is requested. GNU
`returns_twice` attributes and the hosted `setjmp`, `_setjmp`, `sigsetjmp`, and
`__sigsetjmp` interfaces select the profile; a same-named internal function does
not. Function types do not carry this declaration property, so every indirect
call conservatively selects the same profile; known ordinary direct calls do
not. A function that also contains runtime-sized automatic storage is rejected
until arena checkpointing is proven. Native tests modify volatile and unchanged
non-volatile locals, jump across nested calls, and cross-link against the system
implementation under every accepted optimization spelling.
